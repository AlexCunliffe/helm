# Security reports

Use the repository's private vulnerability reporting form when it is available. Do not put credentials, exploit details, or private task content in public issues. If private reporting is unavailable, open an issue that asks for a private reporting channel without disclosing the vulnerability.

This reference implementation has no support agreement or guaranteed response time. Read [the security model](docs/security.md) before installing it.

Keep each deployment's credentials separate. Use a development deployment for tests. Do not commit local configuration or secrets.
